# Django Management Commands

В этом документе описаны кастомные консольные команды (`manage.py`), реализованные в проекте **Hypn0** для автоматизации периодических фоновых задач, скоринга и обслуживания хранилища.

---

## 1. `rescore` — Пакетный пересчет рейтинга и детекция аномалий

- **Путь:** `hypn0/hypn0_site/management/commands/rescore.py`
- **Назначение:** Пакетный фоновый пересчет рейтинга популярности (`f_score`) для всех активных картин и выявление аномалий (накрутка лайков / скоординированный шейминг).

### Базовый запуск:
```bash
# Рабочий запуск
poetry run python hypn0/manage.py rescore

# Тестовый прогон (без записи изменений в базу)
poetry run python hypn0/manage.py rescore --dry-run
```

---

### Архитектурные принципы и алгоритм:

1. **Метрики платформы («Средняя температура по больнице»):**
   - Анализирует активность за скользящее окно `WINDOW_HOURS = 24.0` часов.
   - Считает среднее число голосов на одну активную картину (моложе 30 дней).
   - **Защита «холодного старта» (Cold Start):** при пустой базе или отсутствии голосов отключаются относительные детекторы, предотвращая ложные срабатывания и деление на 0.

2. **Экспоненциальное затухание голосов (Time-Decay):**
   - Сила каждого голоса из `TbVote` плавно затухает по закону:
     $$\text{Weight}(t) = \text{BaseWeight} \times 2^{-\Delta t / \text{HalfLife}}$$
   - По умолчанию период полураспада силы голоса составляет 14 дней (`--half-life-days=14.0`).
   - Истинные веса голосов:
     - `LIKE` = $+1$
     - `AUTHOR` = $+2$
     - `CLAIM` = $-2$

3. **Детекция аномалий и автоматический перевод уровней (`Level`):**
   - **Шейминг (`Level.SHAMED = -20`):** если за последние 24ч доля жалоб среди свежих голосов $\ge 35\%$ (`--shame-claim-ratio=0.35`).
   - **Накрутка / Спайк (`Level.SUSPICIOUS = -10`):** если приток лайков за окно в 4+ раза превышает средний по платформе (`--spike-multiplier=4.0`) и составляет $\ge 20$ лайков (или $\ge 50$ лайков при холодном старте).
   - **Прогрев (`Level.LEVEL_1 = 10`):** если картина со статусом `CANDIDATE` набрала достаточный взвешенный вес ($\ge 10$ по умолчанию), она автоматически повышается до `LEVEL_1` («Плеск бессознательного»), привлекая внимание модератора для витрины.

4. **Гравитационная модель скоринга (с логарифмом):**
   $$\text{Score} = \frac{\ln(1 + \max(0, \text{WeightedLikes})) + \text{Bonus}_{\text{level}}}{(\text{Age in hours} + 2.0)^\gamma}$$
   - `CANDIDATE_BONUS` = $+1.0$ (Свежая генерация)
   - `LEVEL_1_BONUS` = $+1.5$ (Плеск бессознательного / прогрета)
   - `LEVEL_2_BONUS` = $+3.0$ (Одобрено Мозговым Слизнем)
   - `IMMORTAL_BONUS` = $+5.0$ (Глубокий транс / Золотой фонд)

5. **Инерционное сглаживание (EMA — Exponential Moving Average):**
   - Чтобы исключить резкие скачки рейтинга от разовых всплесков, итоговый `f_score` сглаживается с предыдущим значением:
     $$\text{Score}_{\text{final}} = 0.7 \times \text{Score}_{\text{new}} + 0.3 \times \text{Score}_{\text{old}}$$

### Параметры командной строки (CLI):

| Флаг                       | Тип     | По умолчанию | Описание                                                         |
|----------------------------|---------|--------------|------------------------------------------------------------------|
| `--gamma`                  | `float` | `1.5`        | Коэффициент гравитации старения картины                          |
| `--half-life-days`         | `float` | `14.0`       | Период полураспада веса голоса (в днях)                          |
| `--spike-multiplier`       | `float` | `4.0`        | Множитель спайка лайков для детекции накрутки                    |
| `--shame-claim-ratio`      | `float` | `0.35`       | Доля жалоб для признания скоординированного шейминга             |
| `--warmup-votes-threshold` | `int`   | `10`         | Порог взвешенных голосов для автопрогрева `CANDIDATE -> LEVEL_1` |
| `--dry-run`                | `flag`  | `False`      | Пробный запуск без изменения записей в БД                        |

## 2. `rehash` — Проверка целостности и перегенерация `s_hash_id`

- **Путь:** `hypn0/hypn0_site/management/commands/rehash.py`
- **Назначение:** Синхронизация публичных коротких хэшей `s_hash_id` в базе данных с текущим значением `HASHIDS_SALT` и `HASHIDS_MIN_LENGTH`.

### Когда требуется запуск:
1. При смене или ротации `HASHIDS_SALT` в `.env` / `settings.py`.
2. При переносе/миграции базы данных между разными окружениями (Dev -> Prod).
3. При обнаружении записей с пустыми или устаревшими `s_hash_id`.

### Базовый запуск:
```bash
# Тестовая проверка нестыковок (без записи в БД)
poetry run python hypn0/manage.py rehash --dry-run

# Боевая перегенерация
poetry run python hypn0/manage.py rehash
```

### Параметры командной строки (CLI):
| Флаг           | Тип    | По умолчанию | Описание                                                       |
|----------------|--------|--------------|----------------------------------------------------------------|
| `--dry-run`    | `flag` | `False`      | Только проверить нестыковки без изменения базы данных          |
| `--batch-size` | `int`  | `500`        | Размер пачки для `bulk_update` (оптимизация памяти и скорости) |

## 3. `rename_generations` — Массовое переименование названий генераций (`s_title`)

- **Путь:** `hypn0/hypn0_site/management/commands/rename_generations.py`
- **Назначение:** Пакетный перевод и актуализация названий генераций (`TbHypn0Item.s_title`) на английский язык с использованием генератора гипнотических тайтлов (`generate_hypno_title`).

### Когда требуется запуск:
1. При переводе проекта и базы данных (Dev / Prod) на английский язык для замены существующих русскоязычных названий.
2. Для заполнения пропущенных или пустых названий генераций.
3. Для пакетного обновления всех названий с новым детерминированным смещением (`--seed-offset`) или случайными сидами (`--random`).

### Базовый запуск:
```bash
# Тестовый прогон: просмотр примеров изменений без сохранения в БД
poetry run python hypn0/manage.py rename_generations --dry-run

# Боевое переименование (по умолчанию только записи с кириллицей или без названия)
poetry run python hypn0/manage.py rename_generations

# Переименовать абсолютно все генерации в базе данных
poetry run python hypn0/manage.py rename_generations --all

# Переименование со случайными сидами и лимитом записей
poetry run python hypn0/manage.py rename_generations --random --limit=100
```

### Параметры командной строки (CLI):
| Флаг             | Тип    | По умолчанию | Описание                                                                            |
|------------------|--------|--------------|-------------------------------------------------------------------------------------|
| `--dry-run`      | `flag` | `False`      | Тестовый прогон: вывести примеры изменений без записи в базу данных                 |
| `--all`          | `flag` | `False`      | Переименовать абсолютно все записи (по умолчанию только с кириллицей или пустые)    |
| `--only-cyrillic`| `flag` | `True`       | Переименовывать только записи с кириллическими символами в названии                 |
| `--batch-size`   | `int`  | `500`        | Размер пачки для `bulk_update` в транзакции (оптимизация нагрузки на БД)           |
| `--limit`        | `int`  | `None`       | Ограничить максимальное количество обрабатываемых записей                           |
| `--seed-offset`  | `int`  | `0`          | Смещение для детерминированного генератора сидов (`seed = item.id + seed_offset`)   |
| `--random`       | `flag` | `False`      | Использовать недетерминированные случайные сиды вместо ID записи                    |

## 4. Планируемые команды (Roadmap)

- **`cleanup_storage`** — Удаление старых и низкорейтинговых картин (Smart Retention) при превышении квоты хранилища (использует рассчитанный `f_score`).
- **`cleanup_reports`** — Автоматическая изоляция или удаление картин со статусом `SHAMED` после истечения тайм-аута модерации.
